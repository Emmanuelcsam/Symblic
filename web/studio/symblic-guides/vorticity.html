Constructing a finite energy witness

Select Discrete vorticity construction in the native Write examples, or run:

tools/symblic run examples/vorticity-construction.sym --by ollama:qwen3:4b-instruct --max-calls 30 --dir /tmp/vorticity-run

This applies the energy construction in the supplied Energy method for the vorticity equation to a declared, dimensionless finite graph. It is a small model-construction task with an independent exact checker. The continuum equation is div(y grad(phi)) = Omega, with positive y = mn/B², prescribed potential on a nonempty boundary part and zero normal derivative elsewhere. Its weak form gives a negative source load; the energy is integral(y |grad(phi)|² / 2 + phi Omega).

The example chooses five equally spaced vertices, zero endpoint potentials, four unit edge weights and interior source loads [0,-2,0]. The reduced incidence matrix D maps three interior potentials to four edge differences. The finite stiffness is A = transpose(D) W D and b = -loads, so the reduced energy is xᵀ A x / 2 - bᵀ x. The sign of b is part of the check.

Twenty fresh model tasks construct six independent coefficients of the symmetric stiffness matrix, five nontrivial LDL factors/pivots, and nine scalar substitution values that determine the three interior potentials. Each coefficient ask receives only its one or two selected incidence columns and the weights. It constructs one scalar weighted dot product. The host extracts columns and assembles the model's checked coefficients into the symmetric matrix; it does not supply a stiffness answer to the worker. Before the first factor ask, an independent assertion checks every assembled entry against the original incidence matrix and weights.

Every ask uses medium effort and receives named inputs only. Coefficient identities, the complete matrix identity, factor identities, positive pivots, the stationary residual and the final quadratic witness are checked. A failed check retries its generating task once. The thirty-call host budget includes these corrections. The model constructs the answer: determination, solving and the optional constructor are disabled. The shared quadratic checker verifies the supplied factorization without computing it. Expected fixture answers below are not sent in coefficient requests.

The rational record has an unrestricted signed integer numerator and a denominator in 1..100. All rational-factor and substitution instructions explicitly say the numerator may be negative, zero, or positive, and only the denominator must be positive. The three pivot tasks still require a positive pivot through their equations and independent checks; off-diagonal factor entries retain their required signs. No expected numeric factor answer is inserted into a construction prompt.

The final solve is also decomposed. Each worker constructs one value from only its named scalar inputs; prompts explicitly request multiplication then subtraction, division, or copying those selected values. The host checks the defining identity before the next worker can use it:

Value Exact check Selected inputs
y1 y1 = b1 b1
y2 y2 + l21*y1 = b2 b2, l21, y1
y3 y3 + l32*y2 = b3 b3, l32, y2
z1 d1*z1 = y1 y1, d1
z2 d2*z2 = y2 y2, d2
z3 d3*z3 = y3 y3, d3
x3 x3 = z3 z3
x2 x2 + l32*x3 = z2 z2, l32, x3
x1 x1 + l21*x2 = z1 z1, l21, x2

The first six substitution answers use signed rational records. The three backward answers use Int for this declared integer-solution fixture. The host extracts b1,b2,b3, converts rational records to exact numbers and assembles the accepted answers into solution; it does not calculate substitution answers. The full A*solution-b check and quadratic witness verification remain independent of those local identities. Changing the problem can require a rational solution type and corresponding author contract.

For the checked fixture, the full potential is [0,1,2,1,0], its residual is zero, and its reduced energy is -2. The fake provider derives replies from the selected request data. Tests inject a wrong coefficient, corrupt matrix assembly, reject wrong forward, diagonal and backward proposals, and catch a corrupted assembled solution. A load change to [0,-4,0] has the integer solution [2,4,2] and rejects retained old backward answers through their identities. Solving/factorization functions raise if invoked. These tests establish the construction/checking path, not small-model success. Real model performance must be recorded separately.

The source and run receipt (local repository: evidence/2026-10-05-vorticity-construction.json) records its pins, canonical witness and replay result.

This finite connected graph with fixed endpoints has a positive definite reduced operator. It does not establish continuum convergence, dimensional plasma calibration, a GPU implementation or general pure-Neumann solvability. Those extensions need their own geometry, units, compatibility conditions and validation.
