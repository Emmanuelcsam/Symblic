## 3. What autogen is, in one paragraph

A run is the usual list of precise statements. For each statement the coordinator launches up to `candidates` independent attempts, each an ordinary durable task in its own checkout (the hub's own-checkout path locally, the provisioned checkout on a worker node; the prompt is localized to that checkout and carries the checkout lock). Code decides: named files must exist and be in the attempt's change set, syntax checks by extension, the operator's public commands, a completed task, and the task engine's claim-versus-disk warning. The first passing attempt is promoted (commit, then apply into the project) and the losers are cancelled. Failures are classified (`INFRASTRUCTURE`, `REFUSAL`, `NO_OUTPUT`, `SYNTAX`, `CHECK_FAILURE`, `CLAIM_MISMATCH`, `CONTEXT_EXHAUSTED`, `TIMEOUT`, `CANCELLED`, `CONFLICT`, `FETCH_FAILURE`, `HIDDEN_FAILURE`, `UNKNOWN`) and drive a regeneration rotation (feedback from public check output, another machine, another agent type, fresh; cycles refused by fingerprint). When regeneration is spent and the failure is semantic, one planner attempt splits the statement into 2 to 8 smaller statements, validated by code (no named file may be dropped); the parent is accepted only when its own checks pass after the children. A worker near its context limit writes `AUTOGEN-CHECKPOINT.json` and `HANDOFF.md`; a validated checkpoint spawns a successor in the same checkout (remote handoff is refused until the task engine exposes `workspaceFrom`). Perpetual lanes re-spawn a bounded generation after an interval with the cursor of the last promoted generation. One global budget (`agents_max`, `wall_seconds`) bounds everything; every intent is written before dispatch and child request ids are deterministic, so a crash never launches a duplicate.

**Implemented and tested** (`symblic/autogen/policy.py`, `symblic/autogen/coordinator.py`; suites `tests/autogen/test_policy.py`,
`tests/autogen/test_coordinator.py`, `tests/integration/test_symblicos_autogen_hub_lane_v2.py`: 205 tests OK, fakes only):
- `until_done`: `agents_max` and `wall_seconds` default to 0 (unlimited); an explicit value is a safety cap. A node
  regenerates while an untried strategy fingerprint exists or the last attempt made code-verified progress (a new
  named file or more checks passing; worker-written "done" lists and junk files are not progress). After
  `novelty_limit` attempts without progress (timeouts and checkpointed handoffs count, other machines' failures do
  not) the statement is split; a refused split is re-planned on an untried engine/node; when nothing novel remains
  the run is `stuck`, never `failed`. `resume` starts a new rotation (fingerprints archived, strategy quotas reset,
  handoff chains reopened, catalogue re-read); a spent explicit cap needs `extend` (`--agents-max`/`--wall-seconds`
  on `symblic-task autogen resume`).
- Subdivision mechanisms: worker self-split (`AUTOGEN-SPLIT.txt` from a failed attempt becomes the planner; rivals
  are superseded; refused at the maximum depth and on perpetual lanes, and not offered there); stall split; split of
  the remaining work after two handoffs without progress, with the chain's checkout promoted first; a split parent
  whose assembled result fails its own checks is reopened as a whole (`integration` attempt) instead of failing.
- Test designer (CodeT/AgentCoder): an independent agent writes `AUTOGEN-TESTS.sh` first; code admits it only when
  it parses and fails (exit 1..123) on an empty folder; it then gates every candidate as the `designed` check, run
  against a throwaway copy of the candidate's files inside a transient systemd scope (`a systemd slice for work`, TasksMax 64,
  MemoryMax 1G) through the repository's Landlock launcher (no network, no HOME, only the copy writable). A test that
  alone blocks two candidates in a row is retired. `design_valid` is advisory; UDP is not blocked.
- Perpetual lanes: a promoted generation's `items` are keyed (DOI, URL, text) and appended once to
  `AUTOGEN-INDEX.jsonl` in the project folder; the next generation is told the known keys; `saturation N` stops a lane
  after N generations with nothing new; a promoted generation resets the lane's tried-strategy memory.
- Reviews folded: ChatGPT-style local Opus adversarial review (14 findings), Claude cloud review
  `autogen-v2-review-20261010` (5 findings), the docs lane's code audit (7). Every finding is closed except the two
  documented limits above (advisory regex, UDP).
