# Research adoption for Symblic

Research and engineering plan · implementation status updated 5 October 2026

Symblic can use much more mathematics than its current kernel implements. The productive question is what representation, algorithm, assumptions and experiment make each proposed connection useful. Quantum probability, tensor semantics, optimization, geometric integration and formal proof are legitimate software subjects. Their relevance must be established for a specified task; neither an enthusiastic analogy nor a later blanket retraction settles it.

This document separates implemented finite constructions from further research proposals. It contains no private conversation or unpublished source material. The primary sources linked below support the mathematical constructions; proposed applications to Symblic are our engineering hypotheses.

## What we already have

The existing architecture separates model interpretation, exact computation, empirical evidence and external effects. Preserve that separation while extending it.

| Existing component | Reuse it for | Boundary |
|---|---|---|
| `symblic/intent/records.py` | Immutable request/source text, source SHA-256, exact Unicode code-point quote spans, requirement IDs, operator corrections, assumptions, questions, examples and revision checks | A valid quote establishes text identity, not entailment. Preserving a requirement record does not prove generated code implements it. |
| `integration/host/symblic_intent_api.py` | Bounded analysis and compilation through the host executor, explicit clarification requests, execution artifacts | Current artifacts check syntax, types and effect contracts. Readback examples are proposals unless separately executed. |
| `symblic/kernel/evidence.py` | Observed model/node, declared methods, source and assumption dependencies, repair/oracle exposure | Methods and model families do not establish statistical independence. Predicate receipts list direct expression bindings; this is not a complete graph of bindings read inside called functions. |
| `symblic/adapters/variational.py` | Bounded rational symmetric-positive-definite quadratic minimization and checked witnesses | The supplied finite quadratic has a unique minimizer; this says nothing by itself about language meaning or physical adequacy. |
| Runner, lock and execution modules | Finite search, refusal, durable budgets, recorded replies, version/source/capability pins | Recorded replay differs from fresh model generation. Resource exhaustion is a distinct outcome, not a proof of falsehood. |
| Effects and the host executor | Admitted actions, flow labels, original-request recovery and explicit uncertainty | A compensating action cannot generally erase the original effect. Existing operator full/guarded policies remain authoritative. |

The current 2.3 development plan already covers richer retry feedback, repeated-rejection hints, empty-value warnings, option-order permutations, numeric median/tolerance voting, model-lineage reporting, numeric quote grounding, shared-record-field agreement, visible passed checks and a two-account example. The additions below extend that plan rather than recreate it. Their release status must be taken from the implementation review, not this document.

## Highest-value additions beyond that plan

1. **Connect requirements to checks.** Add an artifact-side coverage map from existing requirement IDs to an exact source/AST location, predicate receipt and finite-example receipt. Distinguish `mapped`, `executed_pass`, `executed_fail`, `not_executed` and `unmapped`. Mapping a sentence to a predicate is initially a proposal; preserve its author and operator corrections. A static syntax pass must not mark all requirements covered. Revision, source or predicate changes invalidate the map. Tests: two requirements with only one checked; a check of the wrong field; an unreachable check; operator retirement; stale source; and a syntactically valid constant-output program. The first useful result is visible missing coverage, not an automatically claimed proof of intent.

2. **Extend existing quote references to extracted fields.** Reuse the intent source-reference shape `{source_id, source_sha256, start, end, quote}` and its code-point convention. Add the extracted field path, exact parser/normalization identity and optional entity, unit and polarity fields. Keep original text and parsed value separate. Verify source identity, span, numeric interpretation and field association where a deterministic rule exists. Tests: repeated amounts for different items, negated claims, multiple currencies, Unicode, stale text, overlapping legitimate evidence and a correct number quoted from an unrelated clause. Do not forbid all overlapping spans: one phrase can legitimately support several fields. A quotation remains evidence of occurrence, not a general entailment oracle.

3. **Make executable documentation mechanically accountable.** Inventory every fence as `executable`, `expected_failure` or `proposal`, with checker version, fixture inputs, fake capabilities and expected result. A fixed set of old examples cannot validate newly added syntax. Run executable fences without providers or host effects; record excluded proposals explicitly. This supplies a small, repeatable language-conformance target and prevents an attractive pseudocode example becoming an accidental feature promise.

4. **Add explicit partial answers and repair diagnosis.** Provide library conventions for `supported`, `contradicted`, `missing`, `ambiguous` and `not_checked`, each with witnesses. Preserve conflicting readings instead of forcing an enum member. Distinguish unavailable provider, malformed reply, impossible finite predicate, exceeded budget and unresolved interpretation in receipts. Reuse existing contradiction detection and ambiguity refusal. A failing check does not identify which premise is wrong; diagnostics should present evidence and possible causes without silently rewriting the operator's specification.

5. **Measure complementary methods on shared failures.** Extend the existing evidence ledger with a benchmark matrix of independently labeled cases and per-method errors. Compare two readers of one source with a reader plus an external record, deterministic parser, numerical checker or adversarial fixture. Report joint errors and what each added method uniquely catches, not an invented independence count. Keep first attempts, repair-exposed answers and held-out tests separate. This is the operational application of observation-mode diversity, with no claim that labels alone prove independence. [Stegenga and Menon](https://doi.org/10.1086/692141).

6. **Develop small mathematical adapters behind explicit contracts.** Exact one-dimensional transport and affine projection now have bounded implementations in Symblic 2.3. Use those precise inputs and checkable outputs as the standard for further adapters before applying them to uncertain semantic data. Neither should replace the current exact kernel with unbounded numerical optimization.

## Quantum mathematics and semantic models

| Proposed possibility | Concrete construction or experiment | What would count as progress; limit |
|---|---|---|
| Quantum probability, density matrices and question order | Fit small, explicitly normalized quantum-probability and classical contextual models to the same ordered-question dataset; evaluate held-out likelihood, calibration and parameter cost. Keep the predictor outside hard Boolean checks. | Test the model's constraints, including question-order predictions. Unequal conditional probabilities alone are ordinary probability, not evidence of quantum behavior. A fitted density matrix does not reveal an LLM's actual internal state. [Wang and colleagues](https://jbusemey.pages.iu.edu/quantum/PNAS2014.pdf). |
| Orthomodular logic and noncommuting projections | Implement an optional finite rational-matrix toy algebra: check idempotence, symmetry, commutators and composition on explicit inputs. | Distinguish operator order from Boolean logic over fixed facts. Keep existing `and` semantics; do not silently reinterpret assertions as quantum propositions. This is a mathematical modeling experiment. |
| DisCoCat, tensor semantics and quantum NLP | Compare a small compositional tensor pipeline with existing structured extraction on subject/object reversal, negation and paraphrase. Use an isolated existing library before designing new syntax. | Measure semantic-task accuracy and resource cost. The framework gives a composition rule, not guaranteed correct word meanings. [DisCoCat](https://arxiv.org/abs/1003.4394), [lambeq](https://arxiv.org/abs/2110.04236). |
| ZX-calculus and exact algebraic amplitudes | An optional bounded circuit/tensor adapter can check supported rewrites by exact matrix equality. Restrict phases to a declared number field and version it. | Sound circuit equalities can be verified. Completeness and confluence are distinct; results for stabilizer fragments do not establish a unique natural-language normal form. [Backens](https://arxiv.org/abs/1307.7025), [Biamonte and Nasrallah](https://arxiv.org/abs/2301.05717). |
| POVMs, decoherence and soft verification | For a declared probabilistic model, validate positive measurement operators and normalization and report predicted probabilities separately. Compare with calibrated classical scores. | A probability threshold is a decision policy, not a passed exact predicate. Software may simulate quantum measurements; renaming a contract “decoherence” does not justify its probability model. |
| Ising/QUBO, annealing, QAOA/VQE and ground states | Encode a small finite optimization problem; compare exhaustive enumeration, a classical solver and optional seeded heuristic search. Check every returned candidate against the original constraints. Record objective, gap/lower bound when justified, degeneracy and search budget. | A seed can make a specified implementation repeat exactly; it cannot guarantee optimality or polynomial runtime. SPD optimization over continuous variables differs from binary optimization. [Lucas](https://arxiv.org/abs/1302.5843). |
| Quantum speedups | Use published algorithm assumptions and resource estimates for a concrete supported problem; compare with the best available classical baseline. | No general polynomial-time result follows from an Ising encoding. Specific adiabatic algorithms have hard instances; this does not prove every alternative path fails. [Altshuler, Krovi and Roland](https://arxiv.org/abs/0908.2782), [Dickson and Amin](https://arxiv.org/abs/1010.0669). |

## Falsification examples and admission into the language

Several small counterexamples should remain permanent research fixtures:

- A consistent invoice extraction can quote the wrong item's amount. Arithmetic plus token occurrence must not be reported as full source fidelity.
- `P(B|A) != P(A|B)` is possible in an ordinary finite probability space. It cannot diagnose quantum cognition by itself.
- The two-spin energy `H(s1,s2) = -s1*s2` has two ground states, `(1,1)` and `(-1,-1)`. An Ising encoding does not guarantee a unique answer.
- Two readers can agree on the same false statement, giving zero disagreement under a consensus objective.
- A schema mapping can round-trip while assigning the wrong real-world units or entities. Structural equivalence and intended meaning need separate checks.
- A requirement can survive every intent revision while being absent from the generated program's executed checks.

Each experimental adapter should declare inputs, units or domains, exact versus approximate arithmetic, work/memory bounds, version identity and `unknown`/refusal behavior. It should ship with positive cases, counterexamples and an independent result checker where feasible. Keep model proposals and measured evidence distinct. Add syntax only after a useful library or adapter contract survives these checks.

For publication, predeclare tasks, gold-label provenance, split rules, metrics and total budgets. Include all failures in the denominator. Distinguish syntax validity, checked feasibility, source fidelity, intended-task success, refusal and cost. Use paired cases and report uncertainty and shared-error structure; repeat on a held-out domain. A result can be valuable even when it improves only one layer. The target is a demonstrably smaller perspective gap and more reliable bounded agents, with the remaining unknowns visible.
