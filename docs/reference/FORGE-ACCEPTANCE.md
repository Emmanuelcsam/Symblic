# Symblic Forge requirement and acceptance map

This maps all 154 named construction units in `idesign1.txt` through `idesign5.txt` to the implementation and its verification boundary. The five files were read completely before implementation. They total 2,148 lines and 96,637 bytes; units continue across file boundaries. Examples and alternatives remain proposals unless the operator explicitly loads the labelled demonstration or accepts them.

This is a traceability ledger, not a claim that arbitrary engineering prose has been formally proved. The deterministic checks operate on declared facts, units, relationships and source contracts. Model refinement generates proposals for review. A compiler pass proves the existing static language checks passed; it does not prove intended behavior was implemented or execute a generated project.

## Source and check notation

- **C**: `symblic/forge/core.py`; tests in `tests/forge/test_symblic_forge_core.py`.
- **Catalog**: `symblic/forge/catalog.py`.

- **E**: `symblic/forge/exports.py`; tests in `tests/forge/test_symblic_forge_exports.py`.
- **API / Store**: `integration/host/symblic_forge.py` / `symblic/forge/store.py`; **A** tests in `tests/integration/test_symblic_forge_api.py`.
- **UI**: `symblic-forge.html`, `symblic-forge.js`, `symblic-forge.css`.
- **B1**: browser journey “Snake keyboard decisions, edited suggestion, provenance, snapshot, reload and branch preserve authority”.
- **B2**: browser journey “demo compiler, seven reproducible exports, immutable handoff and all engineering views are usable”.
- **B3**: browser journey “phone, reduced motion, complete text, XSS data, focus and accessible controls”.
- **B4**: browser journey “model request survives reload without redispatch and explicit stop frees its pending state”.
- **B5**: browser journey “New template project, multiline entry and data-only evidence attachment”. Browser source: `tests/browser/symblic-forge.mjs`; temporary actual API fixture: `tests/browser/forge_fixture.py` (not included).

Additional browser regressions cover 400 accepted requirements with measured render/search time (**B6**), disconnected pre-commit recovery with an explicit exact-identity retry (**B7**), storage failure without dispatch or composer lock (**B8**), and numeric cluster budgets plus structured inventory editing (**B9**). Static registration/private-store/online-WAL backup checks live in `tests/integration/test_symblic_forge_integration.py`. Export provenance regressions verify refusal on changed loaded source before and during validation. **B10** follows ordinary number-word/digit pixel answers through separate acceptance, deterministic area derivation, native compilation and reload. Core quantity tests preserve exact wording and reject ambiguous normalization; export tests preserve accepted fact labels, units and conditions in task capsules.

A named check is a reproducible test target, not by itself a pass receipt. See the [dated release evidence](2026-10-07-forge-integrations-evidence.json) for actual run status.

## Explicit limitations and review obligations

1. **Semantic understanding:** catalogue coverage, exact facts, units and graph contracts have deterministic checks. Arbitrary prose equivalence, every natural-language noun, globally minimal dependencies, all physical impossibilities, and semantic preservation of a model edit require operator review. They are never labelled formal proofs by Forge.
2. **Inventories:** a captured catalogue is evidence from that moment, not a resource reservation. Missing entries in incomplete/cached inventory produce unknown observations. Proven absence is only compared against explicitly complete accepted inventory. Neither changes the conceptual design automatically.
3. **Repairs:** repair proposals pin source hash, actual diagnostic, affected IDs and a bounded region. Preview changes no accepted state. An explicit editor check uses the current compiler and does not make custom source the authoritative generated export. Minimality and unchanged intent remain review obligations.
4. **Execution:** Forge prepares design artifacts. Native Text asks describe bounded work and dependency capsules; accepted checks remain observable instructions. Loading the Snake example, validating, exporting, or freezing a handoff does not implement or run the Snake game.
5. **Authority and imports:** imported accepted decisions retain explicit lineage, but imported compiler/export/handoff receipts are historical. Model outputs and attached evidence enter proposed state. Assumption replacement remains proposed; mapped requirement replacement needs its explicit acceptance action.
6. **Bounds:** native source is limited to 400,000 UTF-8 bytes, per-request model context to 48,000 characters, model reply to 100,000 characters, and a proposed compiler edit to 8,000 characters. Full project/history persists separately from bounded model context. Requests beyond the visible limits refuse rather than silently truncate objective text; long compiler source uses a labelled bounded diagnostic excerpt.
7. **Performance:** the design supplied no numeric latency target. The isolated 400-statement fixture verifies functional scaling and immutability, not a universal response-time promise. Browser and actual-node measurements belong to the release receipt.

Two other integrations of the original host were requested outside these five design documents. They are not part of Symblic or of this repository, and they are not counted as Forge language/compiler capabilities.
