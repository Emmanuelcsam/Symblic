Symblic has a useful core: it can give a model a bounded construction task, check the returned artifact, retain evidence and compose accepted results. Its original guarantee was too strong. Precise wording does not make a model a perfect formal interpreter, and local checks do not automatically establish global task success. The design becomes valuable by representing those gaps and reducing measured failures, not by renaming acceptance as truth.

The strongest critique must also be accurate. An earlier version of this document incorrectly described bounded refusal as unsoundness, conflated proof search with proof checking, claimed discrete rewards prevent policy-gradient learning, and described retry/effect failures without accounting for existing protections. Those errors are corrected below.

## 1. The semantic gap is not closed by a strict schema

There are distinct steps from a person's intention to a program, from a source to a structured value, and from a predicate to the intended success condition. Each can be wrong independently.

A valid record can omit a relevant uncertainty field. A word limit can accept an unrelated summary. A quote can be copied exactly yet refer to a different entity. Exact arithmetic can then faithfully calculate from a false premise. Successful checking proves only the encoded condition at the scope of that check.

Permanent counterexamples include:

| Counterexample | Why the earlier check was inadequate | Reform response and residual limit |
|---|---|---|
| Return `[]` for metals in “copper and tin” | Every returned item occurs in the text is vacuously true | Distinguish item support from completeness; a finite required catalog rejects the empty answer, but an undeclared universe remains unknown |
| Return “Bananas orbit Jupiter.” as a short summary | A word-count bound says nothing about fidelity | Exact extractive rendering and required exception spans can be checked; arbitrary paraphrase remains a proposal |
| Return item count `3` as invoice total `120` with an exact quotation | Numeric occurrence is not field association | Caller-pinned label, entity region, position and unit/currency witnesses; unsupported structure refuses |
| Drop an extra `warning` field during coercion | The retained record loses evidence of uncertainty | Strict profiles reject undeclared loss; compatibility mode records transformations |
| Tighten a statement until all models agree on a default convention | Convergence can be achieved by changing the question | Preserve original requirements and assumptions; separate a candidate rewrite from adoption and measure held-out intended outcomes |

The remaining semantic burden is real. A caller can specify the wrong field template, omit a mandatory exception or choose an inadequate test suite. Stronger witnesses make particular errors detectable; they do not solve arbitrary natural-language grounding.

## 2. More precise steps can still accumulate errors

Making every step small can improve inspectability, but also creates more interfaces, repeated calls, context transfers and opportunities to lose assumptions. A chain with many plausible local outputs can fail its overall objective. Subtasks may not be independent, and a decomposition can destroy the information needed to solve them.

The reform therefore needs required dependency closure, end-to-end obligations, explicit state, composition tests and refusal paths. It must compare different decomposition sizes on the same tasks and budgets. “As small as possible” is not established as an optimal granularity rule.

Fresh generation, exact kernel evaluation and replay are separate. A cache can reproduce a recorded answer without making a new inference deterministic. A unique satisfying answer does not guarantee that a small model finds it. Cross-machine agreement must remain tied to the measured corpus and kernel identity.

## 3. “Moving the programming into the kernel” is a valid concern

If every task requires a handwritten solver in the kernel or a specification containing nearly the full target algorithm, the model contributes less than the framing suggests. The apparent small-model advantage may come from increased human programming, stronger test oracles or a fallback model.

The remedy is a construction/checking separation. A general natural-deduction checker can verify many model-produced derivations without supplying each proof. A test harness can examine synthesized code without generating the implementation. Source witnesses can be nominated by the model and checked against a declared relationship.

The proof-construction interface has injected-constructor checks. The older real-model nested-proof pilot accepted no proofs, with 47 of 51 answered attempts failing before any logical check; it is not evidence that the newer flat or incremental interfaces succeed. The separate task-card pilot also produced no complete accepted project. These observations identify work on the construction interface and model evaluation, while retaining the reusable checker architecture. See [the recorded pilot scopes](REFORM-3.md#local-model-observations).

This does not eliminate the specification and checker cost. Measure human effort, supplied implementation content, maintenance, debugging and total calls. A detailed spec-sheet workflow can be useful while failing to reduce total project effort. The Tetris result is evidence of a particular guided construction, not evidence that the formalization tax has disappeared.

## 4. Proofs, predicates and tests require different language

A JSON schema is not a proposition with a proof term. An `ensure` evaluates a particular encoded predicate; a finite test suite covers its cases. The new proof lane additionally checks a supplied derivation in a named formal calculus. These should have different receipt scopes.

The earlier critique's diagram invoking Python `eval()` was inaccurate: Symblic parses and evaluates its own supported expressions. Its limitations should be assessed in the actual parser, evaluator and adapters rather than inferred from that diagram.

The initial proof checker supports bounded intuitionistic propositional terms. It does not prove premise consistency or parse arbitrary English semantics. Quantified-looking text inside an atom has no quantifier semantics; the separate [finite frontend](FINITE-LOGIC.md), connected in live RC2, expands explicit declared domains into ground formulas. Independent tests can find checker bugs; passing them is not a proof of soundness. [PROOF-TERMS](PROOF-TERMS.md) gives the exact boundary.

The often-stated “choose at most two of soundness, decidability and expressivity” triangle is too imprecise to classify this system. Proof finding and checking have different computational tasks. Refusing an oversized proof does not make an accepted proof unsound. Unsoundness would require an invalid accepted judgment under the specified rules; incompleteness, unsupported syntax and exhausted resources are different failure classes. Proof assistants explicitly separate elaboration and automation from trusted checking. [Lean's architecture](https://lean-lang.org/doc/reference/latest/Elaboration-and-Compilation/)

## 5. Assumptions must not be laundered into established knowledge

The old capsule instruction that everything under `KNOWN` was established and binding overstated what earlier model replies warranted. A later exact computation could hide the origin of its premises behind a stronger-looking result.

The RC2 runtime attaches origin, content identity, dependency pins and scoped receipts to values. A derived result remains conditional on its actual premise lineage. It preserves contested vote status, propagates unavailable support and detects missing or mismatched dependency references. A unanimous model vote does not become an observation. Runtime-generated claims start at revision 1 without withdrawal, and runtime assessment records contain empty disagreement lists. Retry rollback removes rejected claims from the active report registry but retains the attempt trace.

The pure `symblic.kernel.epistemic` evaluator additionally checks supplied revisions, withdrawals and explicit disagreement records, including their effects on dependent support. The separate persistent notebook now connects these operations to local run snapshots, operator edits, retained history and selected-context export in the installed 5 October reform. It passed 28 helper and four API tests plus desktop-light/phone-dark browser journeys using temporary stores and intercepted HTTP. Content revisions clear prior checks and cannot mutate a completed run. Hash-only values and unassessed acquisition independence remain explicit. Those are component-test results; notebook installation is part of the later 5 October release, not a new model benchmark.

There are two distinct treatments of contradiction. Runtime vote policy can mark a result contested and refuse its use; the standalone epistemic evaluator also processes explicit disagreement records. The implemented formal proof calculus still includes elimination of falsity and does not automatically check consistency. A caller choosing inconsistent formal premises can derive arbitrary propositions; a valid proof receipt must continue to disclose that its conclusion is conditional.

Hashes prove neither authority nor truth. Host-created provenance and receipts must not be copied from untrusted model-supplied metadata. Integrity checking helps detect change; it does not authenticate a source by itself.

## 6. Context packing can silently change the task

Dropping a required premise changes the computation a model is asked to perform. The earlier character budget counted some rows but omitted substantial fixed prompt overhead, and could drop a high-weight item while reporting only lower-weight omissions.

The new manifest contract distinguishes required dependencies from optional context, counts exact fixed prompt text, preserves named hashes and reasons, and refuses required overflow. Character or byte accounting must not be reported as exact model-token counting. Provider limits still require the corresponding provider/tokenizer checks.

Preserving selected dependencies also does not prove that the selection captured every relevant part of the user's request. Optional retrieval and compression need adversarial coverage tests and visible losses, especially for entities, scope, dates, units and exceptions.

## 7. The language needs explicit operational distinctions

Several permissive behaviors are hazardous when read as formal notation:

- Unrecognized prose may become a model request. A misspelled assertion must not silently do that in a verified program.
- A Boolean expression is a query, not an obligation. `1 = 2.` can evaluate false while execution completes; `assert 1 = 2.` must fail.
- A function presented as pure can hide a routine/model call unless effects are checked transitively, including defaults and captured dependencies.
- Fuzzy key/enum matching, dropped record fields and rounding can change a statement's significance. Some transformations are useful, but their policy and receipt must be explicit.
- Agreement ties and competing readings must remain contested instead of silently feeding later steps under an authoritative label.
- Legacy Datalog modules share scope; the verified profile in live RC2 uses namespaces keyed by immutable module identity. Scope and migration must remain explicit when programs cross profiles.

The reform profiles address the first five categories while retaining legacy behavior under a disclosed compatibility profile. The verified namespace implementation in RC2 addresses module scope. Editor-assisted migration and broader effect typing remain separate work. Adding these restrictions silently to all old programs would reduce useful capability; additive profiles and explicit migrations preserve it.

## 8. Agreement and optimization can reward the wrong target

Two models can share a false answer, a training source, a prompt exposure or a repair oracle. Provider and family labels are useful provenance but do not establish independent errors. Report joint failures and what each method uniquely catches rather than an invented number of independent votes.

A tightening or routing objective based only on unanimity may select the easiest convention, discard hard cases or leak expected answers through feedback. The operator-intent record and held-out outcome checks must remain outside that objective. Proposed assumptions need explicit adoption semantics; a high convergence score is not consent.

Binary rewards do not make reinforcement learning mathematically impossible. For a stochastic policy, the expected-reward gradient can use a likelihood-ratio estimator involving the gradient of the log policy, rather than differentiating the sampled discrete reward with respect to the output. The actual concern is whether the reward is adequate and whether the learning procedure exploits its loopholes. [Williams' original REINFORCE paper](https://doi.org/10.1007/BF00992696)

Zero, empty and copied answers belong in adversarial training/evaluation fixtures. So do valid empty cases, to avoid “fixing” vacuity by making legitimate tasks impossible. Any learned router or graph optimizer needs held-out evaluation and regression constraints before adoption.

## 9. Agent networks need computational semantics

An LLM is not literally a bagged or boosted decision tree. Transformers implement learned transformations with attention; a decision-tree analogy does not supply their execution or learning semantics. [The original Transformer paper](https://arxiv.org/abs/1706.03762)

An agent network can still be a meaningful higher-level program. It needs typed messages, explicit state, a scheduling and synchronization rule, bounded feedback, stop/cancel behavior, evidence policies and durable recovery. Multiple agents do not automatically become differentiable neurons, independent witnesses or shared memory.

Graph composition and optimization are established research directions. GPTSwarm and TextGrad provide concrete prior systems to compare against. The proposed contribution is stronger checked/evidence-aware composition and measured usefulness, not the mere existence of an agent graph. [GPTSwarm](https://arxiv.org/abs/2402.16823), [TextGrad](https://arxiv.org/abs/2406.07496)

## 10. Security and effects: preserve real protections, test remaining influence

The earlier critique treated `steered` values as if the label automatically erased all trust boundaries. The actual engine retains influence and informs the host; capability and full/guarded policies determine permissible actions. A closed enum limits possible outputs but can still let an attacker choose among consequential alternatives. That residual risk is real and should be evaluated under the actual authority policy.

The earlier rollback example also omitted existing protections. The runner rejects effects/delegation between an ask and a retrying check, including prohibited transitive paths. Durable intent/outcome records prevent blind repeat execution when an outcome is unknown. A rollback of internal state is not a claim that external history was undone.

Remaining work includes adversarial influence tests across implicit control flow and nested capabilities, crash/reconnect tests, visible unknown outcomes, and domain-specific compensation where appropriate. A compensating action is another action, not an erasure of the first. Neither physical analogy nor a proof about a pure subroutine establishes complete application security.

## 11. Numerical exactness is not empirical precision

A rational number can exactly represent the value the program stored while the measurement it represents remains uncertain or stale. Units, dimensions, intervals, tolerance, source entity and valid time are part of the model. Normalization and rounding may hide distinctions that matter for the task.

The quantity component in live RC2 supplies bounded explicit operations and compatibility checks. It does not infer missing units or a correct uncertainty model from prose. Existing exact adapters remain useful on their declared domains; scientific interpretation requires its own validation.

## 12. The existing evidence cannot support broad superiority claims

Earlier results mixed several questions: syntactic validity, agreement, predicate acceptance, independent accuracy and final task success. Some small-model checked successes used stronger cloud fallbacks. A prose scorer based on containing the gold numeral can credit a negated or contradictory answer. Comparing that score with exact typed equality changes the measurement itself.

The reform evaluation contract must predeclare cases, information exposure, checker access, retries, fallback policy, budget and scoring. It must retain every planned outcome, including refusals and timeouts, separate local-only from assisted success, and score the same intended outcome in all conditions. Published synthetic fixtures are not guaranteed to be absent from training.

Report first attempts separately from repair-exposed attempts. Include human specification work and supplied algorithms. Do not infer calibration from a heuristic predictability score, checker soundness from unit tests, or a causal architectural advantage from one completed project.

The later frozen task-card pilot covered two synthetic projects across three local models: six cells, zero complete accepted projects, five check failures and one deadline stop, with no pending cells or stronger-model fallback. Partial acceptance under exposed code checks is not final project success. No complete artifact was available for held-out checks or final artifact equality, so those outcomes were unassessed. This exploratory code/numerical pilot is separate from the older proof pilot and from any matched superiority experiment. [REFORM-3](REFORM-3.md#local-model-observations)

## 13. Unsupported mathematical language damaged credibility

Claims of a BKM hallucination bound, polynomial annealing, lossless logarithmic context, free univalence transport, conformal immunity and an isomorphism between empirical agreement and objective truth lacked the necessary constructions or measurements. They have been withdrawn in the rewritten conceptual documents.

This does not invalidate the finite mathematical adapters. Nor does it forbid geometry, quantum models, information theory, sheaves or physics as research. Each connection must specify a task representation, assumptions, algorithm and falsifying comparison. [The corrected research program](GRAND-UNIFICATION-AND-STRING-THEORY.md) preserves these avenues without presenting metaphors as deployed mechanisms.

## Is Symblic useful?

It is plausibly useful where a model can construct a result more cheaply than a person can, and a reusable checker can reject important failures more cheaply than solving the entire problem again. Source-linked extraction under explicit contracts, proof construction, tested code units, bounded agent workflows and auditable revision are concrete candidates.

It is less attractive when ordinary code already solves the task simply, when no adequate checker is available but the interface implies certainty, or when writing the specification costs as much as the target program. The reform should make these tradeoffs visible and supply matched comparisons. A credible system can be ambitious while refusing to call unresolved work solved.
