Symblic aims to make models programmable through explicit statements, checkable constructions and composable evidence. A statement may ask a model to derive a proposition, build code, extract a field or propose a decision. The runtime controls what context it receives, what counts as acceptance, how failures are handled and what later computation may rely on.

This preserves the original idea of LLMs as computational backends. It revises the unsupported premise that a sufficiently precise instruction makes a stochastic model a perfect interpreter. Precision is part of the interface; it is not an execution guarantee.

## The concrete architectural claim

The intended composition is:

```text
operator intent and declared assumptions
        ↓ interpretation, readback and versioned contracts
human formal statement / typed construction request
        ↓ bounded model, human or deterministic producer
candidate value + proof / source witness / testable artifact
        ↓ independent checker for the declared obligation
accepted result with conditional evidence, or explicit unresolved outcome
        ↓ typed dependencies, durable state and authority-checked effects
larger programs and agent networks
```

The checker should implement reusable rules and interpreters, not a separate domain solver for every problem. A model can search for a proof while the checker checks its rule applications. It can synthesize a program while a test harness exercises required behavior. It can nominate source spans while code checks an author-declared relationship. Direct exact computation remains a useful alternative when a model would add cost without useful construction work.

The programming burden has not vanished. Someone must specify the task, choose appropriate obligations, build or select the checker and interpret its limits. The reform makes that burden measurable and reusable instead of hiding it in a large specification or claiming that the kernel inferred the user's meaning.

## Four different promises

| Promise | Scope |
|---|---|
| Deterministic checking | A supported pure checker evaluates the same pinned inputs under its declared implementation and resource semantics. Implementation defects remain possible. |
| Recorded replay | Retained replies and effect outcomes can be reused under compatible source, kernel, module and capability pins without asking the provider again. |
| Conditional formal validity | A successful proof receipt establishes the encoded conclusion from the declared premises in its named logic, subject to checker correctness. |
| Empirical task reliability | Success on independently assessed tasks, including source meaning and behavior; this requires measurements and does not follow from the first three. |

Fresh model generation is a separate process. A fixed seed, a narrow type or an unambiguous goal does not guarantee that a provider will produce the same successful witness each time. A unique accepted answer may constrain successful results without guaranteeing that every run finds it. Conversely, several correct proofs or programs may satisfy the same obligation.

## The reform's core components

**Formal construction.** Controlled formulas and proof terms let people write logical statements with explicit connectives and ask models to construct derivations. The implemented initial fragment is intuitionistic propositional logic. The finite-domain frontend is connected through the compiler/API and Logic interface in live RC2, lowering explicit declared domains to ground formulas; general first-order proving and arbitrary prose interpretation are separate work. A proof receipt does not establish empirical premise truth.

**Operational epistemic state.** RC2 values retain origins, exact content hashes, dependency references, assumptions and receipt scopes. A schema pass stays a schema pass. Arithmetic on a model proposal stays conditional on the proposal. The runner preserves contested vote status, propagates unavailable support and detects missing or mismatched references; its generated claims remain at revision 1 without withdrawal and its disagreement lists are empty. The standalone epistemic evaluator also processes caller-supplied revisions, withdrawals and explicit disagreement records. A separate persistent notebook now connects these operations to imported run snapshots, operator revisions, retained history and selected-context export in the installed 5 October reform. Its 32 Python checks and two browser journeys were component checks with fakes and temporary stores. Its content revisions clear earlier checks and do not mutate an already executed run. Hash-only values remain explicit, shared-source readings gain no independence claim, and notebook installation belongs to the later 5 October reform, not the earlier RC2 receipt.

**Source-linked contracts.** Exact spans can establish occurrence. Stronger finite contracts establish selected field relationships, declared coverage and catalog membership. Free-form paraphrases remain proposals unless separately checked under a suitable semantics. Complete enumeration requires a declared universe or other justified completeness method.

**Agent graph execution.** Nodes can be models, code, observations or checkers. Edges carry typed values and evidence requirements. Explicit state, bounded feedback and deterministic scheduling rules allow more than a single vote or sequential prompt chain. A durable implementation must also preserve attempt identity, resource reservations, recovery and effect authority. The reducer prototype and full runtime have distinct completion criteria.

**Measured adaptation.** Prompt changes, routes and graph topology may be optimized against declared objectives. Candidate changes must be evaluated before adoption, with old contracts, held-out cases and regression constraints retained. Optimizing a weak acceptance rate is not the same as improving task success.

**Numerical and mathematical capabilities.** Existing exact arithmetic, Datalog, finite transport, affine projection, SPD optimization, Ising enumeration, knowledge partitions and operator algebra remain useful. Quantity contracts add dimension, interval and provenance information rather than pretending exact rational representation removes measurement uncertainty.

## What “a network of agents” means

A compositional graph can be more general than a fixed mixture of agents: it can have heterogeneous node types, routing decisions, reusable subgraphs, explicit memory and bounded recurrent updates. Its behavior is defined by the actual transition and scheduling semantics.

This idea has prior art. GPTSwarm represents agents and inter-agent collaboration as computational graphs and optimizes prompts and connectivity. Symblic should compare against that work and identify any additional value in its evidence, checking and durable composition, rather than claim that agent graphs themselves are new. [GPTSwarm](https://arxiv.org/abs/2402.16823)

Connecting model APIs does not create ordinary numerical backpropagation through those APIs. A learning claim needs an objective, parameterization, training signal, update rule and evaluation split. TextGrad uses model-generated textual feedback to improve graph variables; that is a concrete optimization method, not evidence that any chain of agents is already differentiable. [TextGrad](https://arxiv.org/abs/2406.07496)

The initial graph implementation need not claim learning to be useful. Deterministic evidence-aware routing and bounded feedback can be evaluated first. Learned routing, graph search, distillation and policy-gradient updates are separable experiments, with provider cost and shared failure modes included.

## “Universal epistemic operating system” as a research objective

The useful meaning of this ambition is a common substrate for keeping statements, evidence, assumptions, computations and actions connected across domains. A user should be able to ask what supports a result, which assumptions it uses, which alternatives remain, what changed and which consequences need re-evaluation.

“Universal” must not mean an algorithm that decides every mathematical proposition, infers every human intention, validates every source or certifies objective truth. Open interpretations and unresolved observations are ordinary states in an epistemic system. Human commitments and value judgments require their actual authority; model consensus cannot supply it.

The philosophical interest in comparing multiple perspectives is retained. Agreement across methods can strengthen an empirical case when their provenance and failure structure are examined. It is not a mathematical isomorphism between empirical adequacy and objective truth, nor a computational proof of a philosophical position.

## Claims this revision withdraws

These statements appeared in earlier conceptual documents. They are not implementation guarantees or scientific results:

| Earlier claim | Correct replacement |
|---|---|
| A BKM bound reduces hallucination below 0.001% | No defined mapping from model errors to the required fluid variables and assumptions, and no corresponding measured error bound |
| Annealing gives general O(N²) constraint solving | The existing finite Ising adapter enumerates a bounded domain; optional heuristic solvers need correctness checks, budgets and measured scaling |
| Renormalization guarantees lossless logarithmic context | Required information is retained or explicitly refused when it cannot fit; optional compression is evaluated for task-specific loss |
| Univalence removes all schema glue automatically | Equivalences and semantic field/unit mappings must be supplied or established; transport does not discover the intended mapping |
| Conformal worldsheets make prompt injection impossible | Security depends on concrete influence tracking, authority boundaries, isolation and recovery; no such topology-to-security theorem is supplied |
| Conservation geometry gives zero assertion failures and indefinite agent stability | Assertions and refusals remain necessary; long-running stability requires tested state, resource and recovery contracts |
| Multi-frame agreement solves symbol grounding and proves objective truth | Source association, conditional deduction, agreement and empirical validity are different claims |
| The system is the world's first or has already exceeded all alternatives | Novelty and comparative usefulness require a defined contribution and controlled comparison |

The mathematical research avenues are preserved with explicit admission criteria in [the research program](GRAND-UNIFICATION-AND-STRING-THEORY.md) and the full [research adoption register](RESEARCH-ADOPTION.md). A numerical adapter implementing an equation is not evidence that the equation models language or cognition.

## Prior systems define the comparison, not the conclusion

| Prior work | Relevant established idea | What Symblic must compare explicitly |
|---|---|---|
| [PAL](https://arxiv.org/abs/2211.10435) | A model generates intermediate programs that a runtime executes | Whether additional witnesses and composition improve outcomes after accounting for supplied code and tool access |
| [LMQL](https://www.sri.inf.ethz.ch/publications/beurerkellner2023prompting) | Language-model programming combines prompts, scripting and output constraints | Constraint expressivity, provider behavior, task success and total inference cost |
| [DSPy](https://arxiv.org/abs/2310.03714) | Declarative model modules form optimizable pipelines | Whether evidence/state contracts add measurable value beyond pipeline optimization |
| [ProofWriter](https://arxiv.org/abs/2012.13048) | Models generate implications and proof structures over specified theories | Proof construction and generalization in the supported formal fragment |

These works support the feasibility of particular ingredients. They do not establish that the present integration is new, superior or universal. A publishable claim needs the actual distinction and its evidence.

## Experiments that could establish value

A useful evaluation separates at least these conditions under the same model, task information and total budgets: direct prompting; typed output; typed output plus matched retries; ordinary tool-assisted execution; model construction with witnesses; and a compositional graph using the same available checkers. A stronger-model condition is reported separately from small-model-only operation.

Predeclare source and code-generation tasks, logical construction families, held-out contract mutations and ambiguous-intent cases. Freeze checker versions and report first-attempt and repaired outcomes separately. Include refusals, timeouts and failures in the planned denominator. Independent assessment must include semantic correctness or behavior beyond the predicates exposed during construction.

The main outcomes are task success, false acceptance, supported-result coverage, cost, latency, recovery failures and human specification/debugging time. Also report how much target implementation was already supplied in examples, setup code and the specification. A successful project requiring its full algorithm to be written into the prompt may still be a useful code-generation workflow, but it does not establish a reduction in programming effort.

Existing Tetris results show that small local models can construct tested components under substantial guidance. They do not establish a universal advantage or replace a matched baseline. The reform succeeds scientifically only if its additional structure improves a stated outcome without concealing the costs or remaining failures.
