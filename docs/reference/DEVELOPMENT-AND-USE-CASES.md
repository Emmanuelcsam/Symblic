# Symblic development roadmap and application candidates

> **AI-written, revised.** The first version of this document was generated by an AI model (Gemini, through
> Google's Antigravity agent) in October 2026 and later corrected against the code by another AI agent. No
> human has reviewed it. See [../MADE-WITH-AI.md](../MADE-WITH-AI.md).

The installed 2.5 reform combines typed model construction, bounded formal checks, exact computation,
source witnesses, evidence lineage and the existing durable execution paths. Installation does not make it a
universal verifier. This roadmap preserves the intended range of applications while separating working
primitives from integrations and research that still need implementation and validation.
[Current specification](SPEC.md), [component status](REFORM-3.md)

## Existing foundations and proposed extensions

| Area | Existing foundation | Proposed work and acceptance boundary |
|---|---|---|
| Types and contracts | Bounded scalar/container types, `assert`/`ensure`, strict coercion, transformation receipts and explicit quantities | Predicate refinements, dependent types, tagged unions and exhaustive matching need a specified grammar and checker. An email containing `@` is not a validated address. |
| Uncertainty | Unknown/conditional/contested support, exact quantity intervals and declared provenance | Distribution/calibration APIs need measured calibration, exposure tracking and applicable population assumptions. An origin label or model vote does not manufacture a probability. |
| Temporal properties | Recorded statements, effects, budgets and recovery outcomes | Temporal-logic monitors are proposed. Define trace semantics, clocks, incomplete observations and deadline failure before adding syntax. `always`/`eventually` examples in the earlier roadmap were pseudocode, not current statements. |
| Human formal logic | Propositional proof terms and explicit finite-domain expansion; models or people construct checked derivations | Richer first-order/inductive fragments and optional Lean/Rocq export need precise translations and independent checking. An accepted exported proof still depends on the adequacy of its formal statement. |
| Solver integration | Exact bounded adapters and unique finite-domain enumeration for supported ask contracts | Optional SMT backends need declared theories, versions, resource limits and model/proof validation. There is no general millisecond bound, and existing `solve=true` does not mean unrestricted SMT support. |
| Natural-language formalization | Interpreter retains operator statements, sources, assumptions and source-pinned predicate-presence mappings | Broader technical-paper/legal/API formalization remains model construction with visible gaps. Parsing or proof acceptance cannot certify arbitrary prose equivalence. |
| Crystallisation and reuse | Explicit finite-domain routine crystallisation, memoisation, compatible locks and accepted-code Keep | Preserve source/model/check evidence in generated tables. Automatic cache promotion must not turn consensus into truth. Measure reuse benefit separately from table-entry validity. |
| Routing and cost | Checked escalation/search, call budgets, registered model placement and recorded attempts | Improve cost estimates and policy selection using matched outcomes. Cloud fallback remains a declared policy choice and must be attributed; local-only tasks remain local-only. Latency/token estimates are predictions, not universal bounds. |
| Agent networks | Typed graph/state reducers; existing parallel asks, votes and admitted fleet paths | Durable graph execution and policy bridges need their own recovery evidence. Bounded cycles, explicit effects and evidence-transfer rules come before learned topology claims. Compare existing agent-graph methods. |
| Debate and critique | Existing council/orchestration paths | Measure adversarial debate, selection and independent checking at matched cost. A third model's selected invariant is still a proposal until independently checked against an authoritative contract. |
| Multimodal inputs | Existing model/capability infrastructure and exact geometry adapters | Add versioned image/audio/sensor inputs, observations and witness types. Perception uncertainty survives conversion to a symbolic record. No current general multimodal `ask` syntax is implied. |
| Editing and packages | Current editor, diagnostics, previews, modules, examples and source pins | LSP support, reactive notebooks and a package registry remain tooling proposals. Package integrity, compatibility and publisher authority are distinct from semantic correctness. No `sympkg` command is currently supplied. |
| Fuzzing and testing | Focused isolated fixtures, source/quantity/proof adversaries and matched evaluation | A property-based generator can seek counterexamples and measure coverage. Finite fuzzing does not prove absence of all violations; no `symblic fuzz` command is currently supplied. |

Agent-graph optimization and textual feedback already have relevant primary comparisons. Their
existence supports studying explicit update mechanisms; it does not establish that connecting Symblic
nodes is novel or differentiable through model APIs.
[GPTSwarm](https://arxiv.org/abs/2402.16823), [TextGrad](https://arxiv.org/abs/2406.07496)

## Application candidates

These nineteen candidates preserve the original application scope. A row names a possible workflow,
not a shipped domain product, regulatory determination or clinical recommendation. The last column
states the additional evidence or integration needed before claiming the domain outcome.

| # | Application | What current primitives can contribute | What remains to establish |
|---|---|---|---|
| 1 | Contract-clause auditing | Retain source clauses and extract typed candidate fields; compare encoded obligations | Correct parties, exceptions, dates and applicable rules need domain validation. A Datalog result is conditional on the supplied clauses and rules. |
| 2 | Ownership/sanctions screening | Traverse declared corporate-ownership relations and compare pinned reference records | Source freshness, identity resolution, list completeness and applicable screening policy are separate inputs. No current legal-compliance claim follows. |
| 3 | Privacy data-flow review | Check reachability in a supplied data-flow model and retain counterexample paths | The model must cover actual runtime flows and authorization rules. Proving no path in an incomplete graph does not prove regulatory compliance. |
| 4 | Tax worksheet checking | Perform exact arithmetic and compare explicit thresholds/formulas | Supply versioned jurisdiction/date rules and explicit exchange-rate observations. `units.sym` is not a currency-rate service. |
| 5 | Medication calculation review | Check declared units, arithmetic and interval propagation on retained inputs | Clinical rules, patient facts, contraindications and validation remain external requirements. Exact arithmetic alone does not establish a safe dose. |
| 6 | Trial-eligibility review | Organize source-linked candidate criteria and evaluate explicit inclusion/exclusion rules | Distinguish missing, negated, historical and current facts; validate rules and retained evidence. No claim that the system eliminates contraindications. |
| 7 | Laboratory recipe checking | Apply stated concentration bases and exact conversion/dilution conventions | Check physical assumptions, calibration, material properties and execution. Percentages need a shared declared basis; volumes are not always additive. |
| 8 | Invoice/receipt matching | Match source-witnessed fields and recompute declared totals | Resolve entity/currency/time mismatches and incomplete evidence. Payments need an authorized registered capability and durable outcomes; idempotency is not inferred from arithmetic. |
| 9 | Supply-chain dependency analysis | Compute closure over declared components and suppliers | Completeness is relative to supplied relations; missing suppliers or time-dependent substitutions can change the result. |
| 10 | Lease/rent schedule review | Retain source dates, caps, indices and conditional arithmetic | Resolve exceptions and provide the actual index observations. Typed extraction does not remove all transcription or interpretation errors. |
| 11 | Advisory/package matching | Compare structured candidate version ranges and dependency snapshots | Package-version semantics, advisory interpretation and actual patch efficacy need independent checks. Installing a listed version does not prove every flaw is resolved. |
| 12 | IAM/RBAC model review | Evaluate declared permission/delegation relations and exhibit paths | Dynamic conditions, external identities and complete provider semantics must be modeled. A graph query alone cannot rule out every real privilege-escalation path. |
| 13 | Checked bug fixing | Construct patches, run declared fixtures and retain regression/performance results | Finite tests establish observed behavior, not guaranteed non-regression. Preserve integration checks and existing review/merge authority. |
| 14 | Host task execution | Translate a request into checked statements and use existing capability ledgers/full-or-guarded policy | Unknown non-idempotent outcomes refuse blind redispatch; this is recovery discipline, not zero risk of duplicate action in arbitrary services. |
| 15 | Mail classification and scheduling | Produce typed urgency/action proposals and carry untrusted-source influence labels | Use existing authorized connector/capability paths and source/recipient checks. An enum does not sanitize influence or grant a message authority. |
| 16 | Cluster workload admission | Consume admitted capacity information and retain placement/power policy decisions | Reuse existing fleet launch paths, reservations and timed leases; do not invent a `cluster.nodes()` builtin or bypass admission. |
| 17 | Executable research papers | Source-map `.symd` statements and replay compatible complete recorded runs | Access to private data, source completeness, compiler omissions and external validity remain separate. Replay does not independently reproduce an experiment's empirical observations. |
| 18 | CAD/geometry checking | Check supported exact convex-polyhedron structure and declared congruence/similarity | `solid_check` has a bounded geometric domain and can be undecided outside it. Manufacturing constraints, materials and any CAD pipeline require separate integration and validation. |
| 19 | Literature evidence extraction | Retain source spans, quantities and declared arithmetic/statistical checks | Study selection, bias, compatible estimands, missing evidence and inferential assumptions remain substantive research judgments. Consistency checks do not prove fraud or establish a meta-analysis result. |

## Evidence needed to advance a candidate

Start with a declared outcome and a bounded contract. Freeze source versions, available examples,
checker access, negative cases, hidden evaluation cases and total budgets. Compare direct prompting,
ordinary deterministic tools and the proposed Symblic workflow on the same information. Include failed,
refused and incomplete cases, human specification effort, latency and compute cost. Demonstrate the
complete UI/API/runtime/recovery journey for any product integration; an installed adapter or isolated
demo is not that integration. [Matched evaluation](MATCHED-EVALUATION.md)

These boundaries leave room for more capable programs. They make a claim reviewable: which part was
constructed, which part was checked, which assumptions remain, and which operational outcome was observed.
