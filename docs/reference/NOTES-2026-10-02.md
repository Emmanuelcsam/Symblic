The answer at the time, in short: **not as worded.**

What was proved:
- Everything the language computes itself is deterministic, byte-identical on 8 machines.
- Every run replays exactly from its record.

- That different LLMs always agree: it is a measured rate.

## 2. What Symblic is, in one paragraph

Symblic is a language of strict statements. Whatever can be decided formally is decided by the **kernel**, so it
comes out identical on every machine whichever agent runs the program. The kernel does exact rational
arithmetic, logic, sets, Datalog rules, exact geometry and drawings. Only an **ask** reaches a model, and an ask
is a contract:
- a typed answer (the type becomes the model's JSON Schema);
- a context policy (none, named results, the last N, all, facts);
- an effort (direct, reasoned, 3 or 5 votes, a round where agents see each other's answers);
- a weight, and optional definitions and worked examples;
- **checks** the kernel enforces, re-asking with the reason when an answer fails.

Every result has a canonical fingerprint, so a run can be replayed exactly and agents can be compared statement
by statement. A **paper** (`.symd`) is Markdown whose code blocks are the program: prose becomes context,
definitions become shared vocabulary, and the paper can be run by several fresh groups of agents to see whether
they reproduce it.

## 3. What was built

### First night
- **The language and runtime:**
  - `symblic/kernel/language.py`: parser, kernel, Datalog, types and JSON Schema, capsule, consensus, static check;
  - `symblic/kernel/run.py`: interpreter and runner units on the worker nodes' behalf, with record/replay keyed by SHA-256;
  - `symblic/providers/applicators.py`: every agent-hub engine, councils, three-agent-pipeline delegation and a host model service, placed on the worker nodes;
  - `integration/host/symblic_engine.py`: the operator-only API.
- **The page** `/automation-studio/symblic.html`: Write, Plan, Runs, Compare, Language, Evidence.
- **Automation Studio nodes:** Agent, Council, three-agent pipeline, Symblic.
- **The benchmark** `symblic/bench/bench.py`: identity, arithmetic, logic and flower suites against ground truth.
- **Kernel identity:** verified on 8 machines (x86_64 and aarch64, Python 3.11–3.13).

### Second phase (this session)
- **Exact geometry** (`symblic/adapters/geometry.py`):
  - a solid must be closed, convex, consistently oriented, every vertex used, and wrap its hull exactly once;
  - congruence and similarity are decided by an exact isometry search, not by a distance fingerprint;
  - sameness levels run from "parses" to "identical record".
- **The convergence compiler** (`symblic/authoring/tighten.py`):
  - probes a panel, diagnoses each ask (converged, ambiguous, capability, format, unreached), has a clarifier
    rewrite it with explicit assumptions (never the answer), and probes again;
  - `tighten_paper` writes the fix back into a paper;
  - `paper_experiment` judges the rewrite on held-out readers.
- **A Tighten screen** on the page, backed by runner units on the worker nodes.
- **Language features:**
  - option definitions: `one of {fruit: "…", vegetable: "…"}`;
  - `ambiguous=true|fail`: every reader lists the statement's other readings;
  - `families=N`: agreement must come from N model makers;
  - a tie at the top is contested;
  - `fail("message")`;
  - a static linter that scores predictability: units with several meanings, slash dates, missing frames, time
    references, rounding without a rule, letter-named options.
- **Reliability fixes from an independent semantics audit:**
  - retries are transactional and follow the knowledge base;
  - parallel `for each` asks no longer share prompt state;
  - kernel results no longer depend on Python's hash seed or digit limit;
  - `eval` of model text cannot run regex;
  - formal-looking lines are kernel statements, and typos are errors;
  - `check` refuses what a run would refuse (definite assignment, ground facts, order-aware rule safety, aligned
    loop lists).
- **Fleet safety:**
  - per-call thermal placement: no new call to a worker node at 85 °C or more until it reads below 75;
  - stopped processes cancel their live agent runs;
  - bounded model outputs.
- **The peer session c2 built the abstraction layer** on top: functions, routines, modules, tests, the standard
  library (units, stats, text, kinship, graphs, dates, constants), `.symd` papers with cumulative context and a
  linter, locks, certification and crystallisation, with page controls for each.
- **The Codex helper sessions audited** canonical forms, aliases, geometry, statistics and semantics. Every
  confirmed defect was fixed in the core.

## 4. What was discovered

### 4.1 First-night measurements
- **Identical by construction.** The two kernel programs gave one fingerprint on all 8 machines, and all four
  drawings were byte-identical.
- **Typed vs plain** (16 questions, 7 applicators). Pairwise identity rose from 62% to 78%. Resampling whole
  questions, the paired gain is **+17 points (95% CI +4 to +30)**, and Krippendorff's α rose from 0.60 to
  0.77. Accuracy was 88% both ways. The first report used intervals that were too narrow; they are corrected.
- **Translate, then let the kernel reason.** On family logic, qwen3:4b went from 60% to 80% and ran about 3×
  faster. Haiku was 15/15 either way.
- **Flowers from essays.** Haiku, Sonnet, Codex, agy and Opus drew the identical, correct flower from all 6
  essays. qwen3:4b got 5/6, llama3.2:1b 0/6.
- **Small-model council.** Five qwen3:4b voting scored 18/18 on generated arithmetic, which the large models
  also solve perfectly, at 20–30× their latency. A round where they saw each other's answers added nothing.

### 4.2 Second-phase measurements
- **The cube ladder** (4 solids × 4 description styles × 9 applicators). A bare "construct a cube" fixes the shape
  only up to size and placement: 38% congruent, 0% identical records. Plain-language size and position made the
  capable agents agree on the solid. A numbering convention made half of all answers byte-identical.
- **Checked style** (technical description plus kernel end-state checks): **32/32 accepted capable answers were
  the identical record** for every object. qwen3:4b reached acceptance 0/5. The checks admit exactly one record,
  which is tested mechanically.
- **The cube paper, narrow context.** The readers never saw the section giving size and position. All four
  capable cohorts first built a corner-at-origin cube; the paper's checks re-asked them with the reason, and all
  four converged on the identical record after exactly 2 re-asks.
- **The cube paper, full context.** Haiku, Sonnet, Codex and Opus each built **the identical record on the
  first attempt, with zero re-asks** (run fingerprint `bf548ea196d3ca27`). qwen3:4b failed both times
  (coverage 4/5).
- **The furnace paper, tightened by machine.**
  - Before: held-out readers (Opus, gemma, granite, phi4-mini) read the steps 4 different ways.
  - After: Opus, **granite3.3:2b and phi4-mini produced the identical, correct run**, fingerprint
    `93a84f87d61c14f4`.
  - None of the three took part in the tightening.
- **The recipe paper.** It reproduced across Haiku, Codex and agy, and **qwen3:4b on the worker nodes' CPUs reproduced the
  same fingerprint twice, independently**.
- **The slurry papers** (c2):
  - "40% alumina slurry with 1% dispersant" reproduced across three model families, but all three dosed the
    dispersant on the whole slurry (2 g), while ceramics practice doses it on the dry powder (0.8 g). (The powder is
    named "alumina" here for publication; see [papers/README.md](papers/README.md).)
  - **Asking readers for alternative readings exposed the hidden default** (two readers listed the dry-basis
    reading).
  - A clarifier told to use the field's convention pinned "1% of the dry alumina", named the choice, and every
    reader then gave 80 / 0.8 / 119.2 g.
- **Tightening, 24 statements with disjoint probe and held-out panels.**
  - Where held-out readers split along a real reading, tightening fixed 3 of 4: marathon (km/miles), billion
    (short/long scale), primary colours (RYB/RGB).
  - It broke two already-clear statements and one control. In each, the rewrite named the excluded reading:
    "not Fahrenheit" led a 2B model to answer −17.77 °C, which is 0 °F in Celsius.
  - Net on fully covered statements: mean held-out agreement 0.889 → 0.917.
- **Certification** (c2). The text routines passed every test for the cloud models. For qwen3:4b, everything
  passed except the summary, which stayed over its word limit after retries and was refused.
- **Crystallisation** (c2). A two-family panel agreed on 20/20 "is it a metal" answers. These were frozen into
  a kernel table that answers with no model and refuses anything outside it.

### 4.3 What the research found
- **The cube hypothesis is true for finite objects.** Any finite structure can be described exactly by a formal
  sentence, and a fixed interpreter can check any description of it.
- **"This goes for everything" is false.** Descriptions of infinite objects are never pinned down, some objects
  have no description shorter than themselves, and no finite text fixes its own interpretation (Wittgenstein,
  Kripke, Quine).
- **"Agents who knew nothing" needs a qualifier.** Readers must share a fixed interpreter; shared primitives are
  a precondition the description cannot supply.
- **People are bad at one-way description.** In one study, recorded Lego instructions produced 39% wrong models,
  against 5% with feedback. None of 193 cancer-biology experiments could be replicated from the papers alone.
  Two people picked the same word for the same thing less than 20% of the time. Writers overrate their own
  clarity.
- **Controlled languages raise agreement but don't reach identity.** Simplified Technical English and EARS
  help; a language that is fully precise, expressive, natural and simple is "practically impossible" (Kuhn).
- **What raises cross-model agreement:**
  - decide in the kernel;
  - close the answer type;
  - define every option;
  - put the deciding criterion in the option's name;
  - show options by value, not letters;
  - turn disagreement into a repair;
  - vote on meaning;
  - count model families, not samples;
  - vote independently rather than debate.
- **Agreement is not correctness.** In one study, 48% of a frontier model's high-agreement answers were wrong.

### 4.4 Lessons about writing statements that converge
1. **Never take from a reader what the kernel can compute.** The furnace "contract" version, which asks only for
   what the computation needs, reproduced by construction. A removed degree of freedom cannot vary.
2. **Checks turn agreement into identity.** When the checks admit one canonical answer, every accepted answer
   is that answer. What remains to measure is coverage.
3. **Checks plus feedback rescue an under-informed reader.** The narrow-context cube arm converged anyway.
4. **The reader must see every earlier section.** A paper is read in order; the narrow context hid the object.
5. **Agreement is not evidence of specification.** A shared default reading is invisible to a reproduction test.
6. **Ask for readings.** Readers who answer identically will still list the other reading they considered.
7. **Choosing a convention is the author's decision.** Tightening makes it explicit and names it; it does not
   make it right. The clarifier should prefer the convention of the statement's field.
8. **Say what to use, never what to avoid.** Naming an excluded reading primes small readers toward it.
9. **Don't substitute a specific instance for a general question.** "The calendar year 2026" needs leap-year
   knowledge; "a common, non-leap year" doesn't. This is the curse of knowledge.
10. **Capable readers share conventions.** A panel of only frontier models misses ambiguity that conventions
    hide; include different families and small readers.
11. **One reader's nuance is weak evidence; a deviation another reader explains is strong evidence.** For
    example, "in miles: 26.2" listed by one reader, and 26.2 answered by another.

### 4.5 Defects found and fixed along the way
- **Audit (Codex helpers):**
  - canonical-form collision between records and tags;
  - conflicting case-variant keys;
  - retries answered from the replay cache;
  - geometry accepting flat or duplicate-face "solids", and homometric point sets as congruent;
  - negative cube sides;
  - non-transactional retries;
  - the parallel prompt race;
  - hash-seed and digit-limit dependence;
  - regex blow-up;
  - unsound `check`;
  - a fractional temperature crashing the replay key.
- **Found in the runs:**
  - phi4-mini placed but launched under the wrong name;
  - unbounded "readings" arrays that let a 1B model generate for 17 minutes;
  - chained rewrites not written back into a paper;
  - over-strict leak detection on closed answers;
  - a one-reader quorum that rewrote clear statements.
- Every one has a regression test. 258 Symblic tests pass.

### 4.6 Operational lessons
- **the host must not run models.** The operator's rule, and the oomd history, say so.
- **Wait for capacity before launching.** Probing capacity by launching wrote about 1,000 failed rows into
  the fleet runner's history on the first night.
- **The worker nodes get hot under hours of model load.** node-i reached 93 °C and node-b 85 °C. Per-call thermal
  placement now keeps work off a hot worker node.
- **The worker nodes' Ollama is capped at 3 GB.** gemma3:4b crashes it; keep it out of panels.
- **Stopping a process with systemctl used to orphan its runs.** One held a worker node's only Ollama slot for
  22 minutes; stopped processes now cancel their runs.
- **Small models on the worker nodes' CPUs take 30–580 s per call under contention.** The 24-statement tightening run
  took about 2.5 hours.

## 5. Answers to the questions of 2026-10-03

### A correction first: what the qwen result showed
The council of five qwen3:4b scored 18/18 on generated arithmetic word problems. Claude and Codex were also
perfect there because the problems are easy for them. The council took about 2 minutes per problem against
4–12 seconds, and the single-qwen baseline was too small to show that the council beat one qwen. So "on par"
holds only for short, checkable statements.

Where qwen3:4b fell short:
- the cube, in every style and in the paper;
- family logic: 80% with the kernel reasoning, against Haiku's 100%;
- a 12-word summary.

Where small models matched the large ones: the recipe paper (qwen3:4b, twice) and the tightened furnace paper
(granite 2B and phi4-mini). The pattern: small models succeed when the paper is precise and the kernel does the
hard part.

### Can light models replace proprietary ones in a CLI?
Not for general coding today. Coding needs long reasoning, multi-file edits and tool use, none of which is
checkable statement by statement. A hybrid can cut proprietary use a lot:
1. **Certify, then route.** Measure each kind of statement (extraction, classification, arithmetic, a procedure
   step) against local models with the certification tool. Route each kind to the cheapest model that passes.
2. **Escalate on failure.** When a local answer fails its check, retry, then fall back to Claude or Codex. The
   check makes this safe: a wrong small-model answer is rejected, not accepted.
3. **Use tests as the checker for code.** A "write this function" statement whose check runs the unit tests is
   the cube pattern applied to code. That is the real path for open models into coding.
4. **Get better hardware for local models.** The worker nodes are CPU-only with a 3 GB Ollama cap, so they top out
   around 4B models. One GPU node running 7–14B coder models (qwen2.5-coder, gpt-oss-20b) would change the
   picture more than any language feature.

### How to make it more deterministic
Determinism comes from shrinking what a model decides:
- **Move more into the kernel.** Add libraries for units, dates (done), stoichiometry, geometry and
  statistics, and a solver (Z3/SMT) so constraints are solved, not guessed.
- **Checks that admit one answer on every model statement.** A tool that proposes checks and counts how many
  answers they admit would make this routine.
- **Contracts, not instructions.** Take only what the kernel needs from the reader.
- **Crystallise unanimous answers into kernel tables.**
- **Measure the new rewrite rules.** A tightening v4 on 50–100 statements would rank what works with enough
  statistical power.

### Strict, logical natural language
This is the field of controlled natural languages: Attempto Controlled English, Simplified Technical English,
Gherkin. The path:
- a controlled-English surface that compiles to the same internal statements, so readers see prose and the
  machine sees logic;
- "Every sample is heated to 600 °C at 5 °C per minute" parses into exact statements;
- undefined words are errors, every term is defined once, no pronouns, and every spatial statement has a frame.

The research document lists 25 rules for this.

### Rewriting the backend in Rust or C
A rewrite would not make it noticeably faster. A model call takes seconds to minutes; kernel work takes
microseconds to milliseconds. A rewrite now would mostly add risk.

Rust becomes worthwhile later, once the language is frozen:
- **A second, independent implementation of the kernel.** Two implementations agreeing is stronger evidence of
  determinism than one.
- **The kernel in the browser,** compiled to WebAssembly.
- **Speed for heavy kernel work:** large Datalog programs, geometry search.

Orchestration stays in Python.

### One agent with memory wipes vs a group
Symblic already gives every statement a fresh context; that is the "memory wipe".
- **One agent plus a checker is usually enough.** In the cube paper each cohort was a single agent, and the
  checks did the rest. When a checker exists, add retries, not voters.
- **Groups help only without a checker, and only when errors are independent.** Five samples of one model share
  its mistakes. Different model makers help more, but research found 60% of shared wrong answers coincide even
  across makers.
- **Groups are good at finding ambiguity.** The slurry default was exposed by readers listing other readings.
  That is the main reason to keep a diverse panel.

So a group is not always necessary.

### Does it improve small models?
- **Accuracy:** yes, where the kernel does the reasoning (60% → 80% on logic) and where a paper pins everything
  down (recipe, furnace). Not where the model must build complex structure itself (cube, summaries).
- **Consistency:** yes. Typed answers, temperature 0 and canonical forms mean that when a small model is wrong,
  the check rejects it. The result is "no answer" instead of a different answer.

### Uses
- **Lab protocols written once and run identically by any agent.** The slurry and furnace papers are the
  template.
- **Reproducible extraction** of data from papers.
- **Classification with defined categories,** such as mail.
- **Spec-to-object work:** geometry, CAD, flowers.
- **Regression testing when models change:** a locked run replays with no model, so drift is visible at once.
- **A growing library of facts** frozen out of models.
- **Teaching:** writing a description precise enough that strangers reproduce it is a skill the tool measures.

### Why it matters
It separates what is computed from what is interpreted, measures the interpreted part, and shrinks it statement
by statement. That is reproducibility for AI-assisted work, which science lacks even without AI.

### Does something like it exist?
The pieces do:
- typed model outputs (Outlines, Instructor, LMQL);
- prompt programs (DSPy);
- translate-then-solve (PAL, Logic-LM);
- voting (MAKER);
- spec repair from disagreement (SpecFix);
- executable specifications (Gherkin);
- literate programming (Knuth).

The combination was not found: statement-level contracts, a deterministic kernel, cross-agent fingerprint
comparison, tightening validated on held-out readers, and papers that fresh groups reproduce
([PRIOR-ART.md](PRIOR-ART.md)). That is "not found in our search", not proof that nothing exists.

### What would heavily improve accuracy
1. **Certification-based routing with escalation,** plus code statements checked by unit tests.
2. **Tightening v4** on a larger statement set.
3. **A solver and domain libraries** in the kernel.
4. **Grounding:** every extracted item must appear verbatim in the source (the `items_in` routine already does
   this).
5. **Decompose judgments** into small yes/no checks combined by rules. Research measured agreement (α) rising
   from 0.09 to 0.48 this way.
6. **Use crystals and locked runs as training data** to fine-tune a small model for a specific class of
   statements.

## 6. What can be claimed now

- **Kernel statements:** identical by construction, on every machine.
- **A model statement whose checks admit one answer:** exactly one accepted answer, whoever applies it.
- **A precise paper** (frame, sizes, conventions, end-state checks): fresh agents from three model makers wrote
  the same cube byte for byte on the first try, and a machine-tightened paper made two small models from other
  families execute it exactly as a frontier model does.
- **Everything open to interpretation:** agreement is a measured rate per panel, which the language raises
  step by step. It is not correctness.

Short form: **"Deterministic where it can be, measurable where it can't, and every gap traced to the sentence
that caused it."**

Avoid: "LLMs become deterministic", "any agent reproduces anything", "the first".
