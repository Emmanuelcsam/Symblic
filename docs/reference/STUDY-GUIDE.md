## 1. What Symblic does

Symblic lets a program give models small, typed construction tasks and decide which returned artifacts
satisfy an explicit contract. Exact arithmetic, Datalog, drawings and bounded adapters remain available;
models can also construct programs, source witnesses and formal derivations for independent checking.
A precise instruction improves the conditions for success but does not force perfect model execution.

Three paths work together:

| Path | Who constructs the result? | What acceptance establishes |
|---|---|---|
| Exact computation | Kernel or a bounded adapter | The specified calculation on supplied values, within the supported domain |
| Checked construction | Human or model | The returned artifact satisfies the encoded checks: for example, inference rules, exact source relationships or finite fixtures |
| Empirical judgment | Model or other observation source | A retained proposal/observation with origin and limitations; agreement does not make it true |

The kernel does not decide all mathematics or understand arbitrary prose. Its exact rational arithmetic
avoids binary floating-point rounding for those operations; transcendental functions are approximations.
A compatible source/kernel/input regime defines intended repeatability, while cross-machine tests cover
only their tested cases. A compatible complete lock replays recorded outcomes without a fresh model call.
Fresh model generation is a separate experiment. [SPEC](SPEC.md), [EVIDENCE](EVIDENCE.md)

This guide describes the installed reform. Existing historical results keep their actual versions;
component tests do not prove general model reliability. The [5 October release evidence](evidence/2026-10-05-reform-install.json)
and [REFORM-3](REFORM-3.md) distinguish scoped live checks, component evidence and remaining work.

## 2. The bridge from human statements to checked execution

English instructions can leave referents, units, scope or exceptions unstated. A formal parse gives an
encoded statement a defined structure, but an `ask` instruction can still be ambiguous. A schema checks
the returned shape and declared ranges; it does not force the provider to answer or establish the truth
of a well-typed result. Provider support for constrained decoding varies. Text remains useful and is
explicitly supported, including text fields inside structured records.

Controlled formal formulas are another interface: quoted propositions plus `and`, `or`, `implies` and
`not`, with optional explicit finite-domain quantifiers. Models or humans build proof terms; the kernel
checks them without inventing a proof. Quoted English is an opaque atom unless a separate caller-authored
formal relation gives it structure. Premise truth and consistency remain outside the proof checker.
[PROOF-TERMS](PROOF-TERMS.md), [FINITE-LOGIC](FINITE-LOGIC.md)

A capsule rebuilds each model request from selected program state. It contains the instruction, types,
selected values, applicable definitions/examples and repair feedback. `from` and explicit context lists
make selected values required. Verified execution counts the system, schema and complete prompt in its
character budget and fails before dispatch if required content cannot fit. Manifests record optional
omissions and exact identities; ancestor lineage does not automatically expand forgotten parent values.
This makes information selection inspectable, without promising a model's full attention, erasing its
training priors or eliminating prompt injection. Paper compilation has an earlier truncation/selection
boundary with its own warnings. [LANGUAGE-3](LANGUAGE-3.md)

Execution profiles make the operational boundary explicit:

- `legacy` preserves earlier programs, including implicit prose asks and historical conversions.
- `explicit` rejects implicit model calls; an ask must be written explicitly.
- `verified` adds transitive function/module-initialization purity, defaults to strict coercion and
  isolated module predicates, and refuses contested votes. Recorded explicit compatibility options
  remain available; “verified” does not mean empirically true or equivalent to the operator's prose.

Use `use profile=verified.` for the examples you intend to run under those contracts. A host can
strengthen a program's profile but cannot weaken it. A bare Boolean expression displays its result;
use `assert` or `ensure` when it is an obligation.

## 3. Language Syntax & Reference

### 3.1 Basic Declarations

An optional `program Name.` gives the run a title:

```symblic
program MyFirstProgram.

# Comments start with # or //
note This is an explanatory note preserved in the run record.

# Defining an input (can be passed via CLI or API)
given user_name: Text = "Ada".
given target_multiplier: Int = 3.

# Single assignment variable binding in the Kernel
let base_value = 10.
let result = (base_value + 2) * target_multiplier.

# Exact rational arithmetic for these operations
let x = 0.1 + 0.2.
assert x = 0.3.           # Passes! Exact rational 3/10

let third = 1 / 3.
assert third * 3 = 1.     # Passes! Exact 1
```

### 3.2 Types

Symblic has a rich, checked type system:

| Type | Example | Description |
|---|---|---|
| `Int` | `42` | Exact integer within the kernel digit/work limits |
| `Int in a..b` | `Int in 1..100` | Integer bounded within range `[a, b]` |
| `Number` | `3/4`, `0.75` | Exact rational number |
| `Number to N places` | `Number to 2 places` | Rational rounded half-up to N decimal places |
| `Bool` | `true`, `false` | Boolean value |
| `Text` | `"hello world"` | Text coercion normalizes NFC/whitespace; canonical stored identity retains exact code points |
| `Text up to N words` | `Text up to 50 words`| Enforces length by word count |
| `one of {a, b, c}` | `one of {gold, red}` | Closed enumeration; fuzzy spelling is a legacy conversion, strict answers use the declared option |
| `List of T` | `[1, 2, 3]` | Ordered sequence (1-indexed!) |
| `List of T length N` | `List of Text length 3`| Sequence with exact or bounded length |
| `Set of T` | `{1, 2, 3}` | Unordered collection with unique elements |
| `Record {k: T, ...}` | `{name: "Ada", age: 30}`| Named fields; `{:}` is an empty record and `{}` an empty set |
| `Code js` (or another supported language) | A final fenced code block | Preserves code text for declared checks; no JSON escaping requirement |
| `Any` | A JSON-like value | Broad shape allowance; acceptance still needs meaningful checks |

Custom named types:

```symblic
define Person as Record {
  name: Text,
  age: Int in 0..120,
  role: one of {admin, member, guest}
}.
```

### 3.3 The Model Bridge: `ask`

`ask` is the explicit core model-construction statement. Routines can contain asks; legacy prose
can become an implicit ask, and delegation/councils have separate orchestration paths.

```text
ask variable_name: Type "Prompt string with {interpolated_values}" [from source1, source2] [with options]
```

**Options:**
- `effort=low | medium | high | max | ultra`
  - `low`: Request an answer without a separate reasoning field; latency is not guaranteed.
  - `medium`: Request reasoning plus a typed answer where supported, or use native provider effort (default).
  - `high`: Default to 3 samples, subject to configured applicators/options; samples need not be independent.
  - `max`: 5 votes.
  - `ultra`: 5 votes, then candidates are anonymized and reviewed in a second round!
- `votes=N`: Requested samples, with at least one per applicator; routing and early-stop options also apply.
- `agree=0.7`: Requested winning share (70%); a contested result fails under verified/strict execution.
- `context=none | all | last N | relevant | facts | [a, b]`: Controls what earlier variables the model can see.
- `by=applicator`: Specifies who answers (e.g. `claude:haiku`, `codex`, `ollama:qwen3:4b-instruct@node-a`, `gemini`).

### 3.4 Verification & Self-Correction: `ensure` and `assert`

- `assert cond.`: A hard check by the Kernel. If `cond` is false, the entire run halts immediately.
- `ensure cond [else retry|fail|warn] [because "reason"].`:
  - When used after an `ask`, `ensure ... else retry` creates a **transactional retry loop**.
  - A failed retry check restores the anchor snapshot and provides bounded feedback before another
    attempt, until the retry/call budget is exhausted. Effects across the retry interval are refused,
    including transitive routine paths. An unknown external action is not rolled back by a prompt.

```symblic
ask spider_legs: Int in 0..20 "How many legs does a spider have?" with effort=low
ensure spider_legs = 8 else retry because "a spider has eight legs".
```

### 3.5 Knowledge & Relational Reasoning: Datalog

Datalog evaluates declared relations and rules, so a model need not perform a graph traversal in prose.
The result remains conditional on the supplied facts; closed-world absence is not real-world falsity.
- `fact predicate(arg1, arg2, ...).` stores ground facts.
- `rule head(X, Y) if condition1(X, Z) and condition2(Z, Y).` creates Horn clauses with logic variables (uppercase).
- `query predicate(arg, Var)` retrieves results.

```symblic
fact parent(ada, ben).
fact parent(ben, cleo).

rule ancestor(X, Y) if parent(X, Y).
rule ancestor(X, Z) if parent(X, Y) and ancestor(Y, Z).

let cleo_ancestors = query ancestor(Who, cleo).
# The single-variable query returns the matching names; compare as a set.
assert set(cleo_ancestors) = {"ada", "ben"}.
```

### 3.6 Functions and Routines

Symblic provides two ways to encapsulate logic:
1. `function`: A kernel expression. Verified execution enforces transitive purity, including defaults;
   legacy keeps a function-to-routine bridge. Runtime is bounded rather than guaranteed instantaneous.
2. `routine`: Reusable, typed LLM procedure with a contract, internal asks, and automatic memoization.

```symblic
# PURE KERNEL FUNCTION
function fahrenheit_to_celsius(f: Number) -> Number = (f - 32) * 5 / 9.

# TYPED LLM ROUTINE
routine classify_sentiment(review: Text) -> one of {positive, negative, neutral} with effort=high do
    ask sentiment: one of {positive, negative, neutral} "Classify this review: {review}"
    return sentiment.
end.
```

### 3.7 Modules & Standard Library

Symblic includes a standard library (`symblic/lang/library/`):
- `units`: Exact conversions under declared unit definitions (inches, meters, pounds, gallons, calories, pascals).
- `dates`: Gregorian date arithmetic, leap years, day-of-week.
- `stats`: Mean, variance, standard deviation, entropy, Fleiss' kappa agreement.
- `constants`: SI defining constants (speed of light, Planck constant, etc.).
- `lab`: Chemistry/biology dilutions, molarity, concentrations.
- `text`: Typed language routines (`yes_or_no`, `choose_one`, `count_in`, `items_in`, `summary_of`)
  with limited checks: item occurrence is not completeness; summary length is not fidelity. Additive
  witnessed routines check exact caller-declared source and coverage contracts.
- `kinship`, `graphs`: Datalog relations for graph reachability and family trees.

Usage:

```symblic
import units.
let cm = convert_length(10, "inch", "cm").   # Exact 25.4

import stats as st.
let m = mean([10, 20, 30]).
let spread = st.variance([10, 20, 30]).
```

### 3.8 External Actions & Observations (`symblic/kernel/effects.py`)

`observe` and `act` use registered capabilities through an injected host and durable outcome ledgers.
Capability names and arguments come from the actual host catalogue, not a generic example's invented
`weather.current` or `email.send`. Existing full/guarded operator policy, information-flow rules, source
pins and preview/replay fences remain in force. Replay serves recorded outcomes; uncertain
non-idempotent actions refuse blind redispatch. This does not guarantee exactly-once behavior for every
external service. [EFFECTS](EFFECTS.md)

## 4. Comprehensive Hands-On Tutorial

### Lesson 1: Your First Script (Math & Model Working Together)

Create a file `spider.sym`:

```symblic
program SpiderStudy.

# Kernel does the math
let pairs_of_legs = 4.
let total_expected = pairs_of_legs * 2.

# Model provides the domain fact
ask legs: Int in 0..20 "How many legs does a typical spider have?" with effort=low

# Check agreement with this caller-declared expected value
ensure legs = total_expected else retry because "four pairs equals eight legs".

# Output the checked values; this check does not establish biological truth
show [total_expected, legs] as "checked_legs".
```
Run it:

```bash
./bin/symblic check spider.sym
./bin/symblic preview spider.sym
```

### Lesson 2: Typed extraction and its limits

A schema and format check can reject some malformed extractions. This example does not check that every
field comes from the source, that the address is the intended destination, or that the quantity is right.
Create `extract.sym`:

```symblic
program OrderExtraction.

given email_body: Text = """
Hi, I ordered 3 wireless keyboards on Tuesday. My order number is KB-98124.
Please ship them to 742 Evergreen Terrace.
"""

define Order as Record {
  item: Text,
  quantity: Int in 1..100,
  order_id: Text,
  address: Text
}.

ask parsed: Order "Extract the order details from the email." from email_body with effort=high

# Verify that the extracted order ID matches the format
ensure starts_with(parsed.order_id, "KB-") else retry because "order IDs must start with KB-".
ensure parsed.quantity > 0 else retry.

show parsed as "clean_order".
```

### Lesson 3: Check a declared access model with Datalog

Suppose you want to manage security access permissions:
Create `rbac.sym`:

```symblic
program AccessControl.

fact user_role("Alice", "Engineer").
fact user_role("Bob", "Intern").
fact role_permission("Engineer", "DeployProduction").
fact role_permission("Engineer", "ReadLogs").
fact role_permission("Intern", "ReadLogs").

rule has_permission(User, Perm) if user_role(User, Role) and role_permission(Role, Perm).

let alice_perms = query has_permission("Alice", Perm).
let bob_perms = query has_permission("Bob", Perm).

assert "DeployProduction" in alice_perms.
assert not ("DeployProduction" in bob_perms).

show alice_perms as "Alice's Authorized Actions".
```
This example makes zero model calls and checks the declared relation. It does not discover missing
roles, dynamic policy conditions or actual infrastructure permissions; no latency measurement is implied.

### Lesson 4: A human-authored proof

```symblic
use profile=verified.
let target = proof_parse('"P" implies "P"').
let certificate = {version: 1, proof: ["implies_intro", "h", ["atom", "P"], ["hypothesis", "h"]]}.
let checked = proof_check({:}, target, certificate).
assert checked.valid and len(checked.used_premises) = 0.
show checked.
```

A model can construct `certificate` instead. The Logic tab compiles caller-held premises, a goal and
optional finite domains into an ordinary checked construction program; compilation itself makes no
model call. An accepted derivation establishes the declared sequent, not the truth of arbitrary English.
Failure to construct a proof does not establish that the goal is false.

## 5. Where to evaluate Symblic

- Source-linked document processing: exact witnesses and required coverage can expose particular
  extraction errors; arbitrary semantic fidelity remains unassessed without further evidence.
- Automation: explicit predicates constrain declared decisions, while authorized capabilities and
  durable ledgers handle effects. A weak predicate does not guarantee a business outcome.
- Model comparison: report agreement, actual target correctness, refusal and cost separately.
- Relational computation: derive consequences of declared facts and keep their source conditions.
- Scientific calculations: use explicit unit/measurement assumptions and appropriate validation;
  rational arithmetic alone does not establish physical or clinical suitability.
- Recorded research: compatible complete locks support replay; they do not authenticate sources or
  independently replicate empirical observations. Private data still requires appropriate access.
- Code construction: `Code js`, isolated JavaScript fixture checks, spec sheets and Keep let models
  build/reuse checked components. Finite passing fixtures still need integration and hidden-outcome
  evaluation. [JS](JS.md), [SPEC-SHEETS](SPEC-SHEETS.md)

## 6. How to Run, Test, and Build Symblic Programs

These commands use the checked-out implementation; model-running commands consume the configured
provider budget and permissions. `check` is static, and `preview` stops before the first ask:

```bash
# 1. Statically check syntax and typing:
./bin/symblic check my_program.sym

# 2. Preview the exact capsule and prompt sent to models:
./bin/symblic preview my_program.sym

# 3. Run a program with an applicator (e.g. Claude or Ollama):
./bin/symblic run my_program.sym --by claude:haiku
./bin/symblic run my_program.sym --by ollama:qwen3:4b-instruct@node-a

# 4. Run unit tests inside a module:
python3 symblic/lang/abstraction.py test symblic/lang/library/units.sym
python3 symblic/lang/abstraction.py test symblic/lang/library/text.sym --by claude:haiku

# 5. Lock a compatible complete run and replay recorded outcomes:
python3 symblic/kernel/lockfile.py lock <run_folder>
python3 symblic/kernel/lockfile.py replay <run_folder>/run.lock.json
```
